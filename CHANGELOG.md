## v2

**Fixed:** `phase2/event_classifier/xgboost_clf.py` was missing a class-based
interface that `phase4/backend/pipeline_runner.py` (and `phase4/tests/
test_phase4_backend.py`) depend on for live video pipeline runs:

```python
from phase2.event_classifier.xgboost_clf import XGBoostClassifier

clf = XGBoostClassifier(sport=sport)
clf.load()
clf.predict_window(window_vectors)
```

Phase 2 previously only exposed a function-based API
(`load_classifier(sport)`, `predict_window(model, sport, vectors)`).
Both interfaces now coexist — the function-based API is unchanged and
still used by `run_phase2.py` and the Phase 2 test suite; the new
`XGBoostClassifier` class is a thin wrapper around the same underlying
functions, added specifically so Phase 4's live pipeline imports
correctly.

No other files changed. No existing behaviour altered.
